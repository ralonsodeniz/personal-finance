## What is available

The developer space describes the accepted monorepo boundaries, the intended
future Expo/mobile relationship, the native authentication flow, and testing
candidates. It also calls out work that has deliberately not been specified.

## What is not available yet

There are no user-facing finance workflows to document yet. In particular,
finance-domain schemas, API resources, CSV import/export behavior, and native
implementation are future work. This keeps the help center from promising
product behavior before the relevant design and implementation tickets are
complete.

When those capabilities exist, user help should be written around tasks and
outcomes rather than exposing the developer package or API taxonomy.
